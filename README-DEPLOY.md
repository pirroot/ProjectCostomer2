# راهنمای کامل اجرا و آپلود — سایت نمونه‌کار عکاسی

سایت: Next.js 16 + SQLite (Prisma) + پنل مدیریت فارسی

---

## ۱) چی لازم داری؟

- **Node.js نسخه ۲۰ یا بالاتر** (از nodejs.org نصب کن — لازم نیست چیز دیگه‌ای)
- همین فایل ZIP

> ⚠️ **نکته مهم هاست:** این سایت با Next.js ساخته شده و به **Node.js** نیاز دارد.
> هاست اشتراکی معمولی (پلن‌های PHP مثل بیشتر پلن‌های میهن‌وب‌هاست) **اجرا نمی‌شود**.
> گزینه‌های درست:
> - **لیارا (liara.run)** — پلن Node.js، ساده‌ترین راه برای ایران؛ دامنه هم مستقیم وصل می‌شود.
> - **یک VPS** (ابرقطر/آروان و…) با Ubuntu + Node.js
> - اگر حتماً میهن‌وب‌هاست می‌خواهی، از آن‌ها بپرس «پلن Node.js» دارند یا نه — پلن PHP معمولی به‌درد نمی‌خورد.

---

## ۲) اجرا روی سیستم خودت (تست محلی)

```bash
npm install          # نصب پکیج‌ها
npx prisma generate  # ساخت کلاینت دیتابیس
```

از `.env.example` یک کپی به نام `.env` بساز و مقدارها را تنظیم کن:

```
DATABASE_URL="file:../db/custom.db"
ADMIN_PASSWORD="admin123"
```

بعد:

```bash
npm run dev          # حالت توسعه → http://localhost:3000
```

- سایت: `http://localhost:3000`
- پنل ادمین: `http://localhost:3000/admin` (رمز: همان ADMIN_PASSWORD در `.env`)

> داخل ZIP یک دیتابیس آماده (`db/custom.db`) با ۱۰ دسته‌ی نمونه و ۸۰ عکس placeholder
> (با برچسب رزولوشن) هست؛ پس از همان اول همه‌چیز را می‌بینی.

---

## ۳) اجرا روی سرور (حالت نهایی)

```bash
npm install
npx prisma generate
npm run build
npm start            # پورت پیش‌فرض 3000 — با PORT=80 npm start عوضش کن
```

اگر دیتابیس را از صفر می‌خواهی (بدون داده‌های نمونه):

```bash
npx prisma db push --accept-data-loss
npx tsx prisma/seed.ts       # یا: bun prisma/seed.ts
```

روی لیارا: پروژه را از طریق `liara deploy` یا اتصال به گیت آپلود کن، یک Disk به مسیر `/app/data` وصل کن و در `.env` بنویس `DATABASE_URL="file:/app/data/custom.db"` — این‌طوری دیتابیس و عکس‌های آپلودی با هر خروج مجدد پاک نمی‌شوند.

---

## ۴) عکس‌ها و دیتابیس — نگران حجم نباش 👍

- عکس‌ها **داخل دیتابیس ذخیره نمی‌شوند**؛ روی دیسک سرور در پوشه‌ی `data/uploads` نگهداری می‌شوند و دیتابیس فقط «آدرس + طول و عرض» هر عکس را نگه می‌دارد.
- SQLite به‌راحتی **صدها هزار ردیف** را مدیریت می‌کند؛ پس ۵۰ یا ۵۰۰۰ عکس فرقی نمی‌کند.
- محدودیت واقعی فقط **فضای دیسک** سرور است (هر عکس بعد از بهینه‌سازی معمولاً ۲۰۰ تا ۵۰۰ کیلوبایت می‌شود — یعنی با ۱ گیگ فضا حدود ۲ تا ۴ هزار عکس جا می‌شود).
- هر عکس آپلودی خودکار تا حداکثر ۲۴۰۰ پیکسل بهینه (JPEG کیفیت ۸۵) می‌شود.

**بکاپ فقط این دو مورد کافی است:** `db/custom.db` + پوشه `data/uploads`

---

## ۵) قابلیت‌های پنل ادمین (`/admin`)

- دسته‌بندی‌ها: افزودن/ویرایش/حذف، جابه‌جایی ترتیب، انتخاب کاور
- **آلبوم جدید همیشه بالای لیست Projects و پنل ادمین می‌آید** (می‌توانی با فلش‌ها دستی هم جابه‌جا کنی)
- عکس‌ها: آپلود چندتایی، ترتیب‌دهی، کاور، حذف
- مشخصات هر دسته (ثابت): `CLIENT` / `PROJECT TITLE` / `YEAR` / `CATEGORY` / `LOCATION` / `ROLE`
- **فیلدهای دلخواه:** تا ۶ فیلد اضافه با عنوان و مقدار دلخواه — خودت اضافه و کم می‌کنی
- **عنوان فارسی:** اگر «عنوان فارسی» را پر کنی، در صفحه پروژه یک دکمه **ⓘ** کنار اسم فولدر می‌آید؛ با کلیک، عنوان فارسی نمایش داده می‌شود
- تنظیمات سایت: **آپلود لوگو** (PNG شفاف بهترین است)، نام سایت، متن About، ایمیل/تلفن/اینستاگرام

## ۶) چک‌لیست قبل از تحویل به مشتری

- [ ] `ADMIN_PASSWORD` در `.env` عوض شده باشد (رمز پیش‌فرض: admin123)
- [ ] لوگو یا اسم واقعی از «تنظیمات» گذاشته شده باشد
- [ ] متن About و مشخصات Contact پر شده باشد
- [ ] عکس‌های واقعی آپلود و عکس‌های placeholder حذف شده باشند
- [ ] بکاپ از `db/custom.db` و `data/uploads` گرفته شده باشد

## ۷) ساختار پروژه (برای مرجع سریع)

```
prisma/schema.prisma     ساختار دیتابیس
prisma/seed.ts           داده‌های نمونه
src/app/                 صفحات سایت و ادمین
src/app/admin/           پنل مدیریت (فارسی، RTL)
src/app/api/admin/upload نقطه آپلود عکس و لوگو
src/app/media/           سرو عکس‌های آپلودی از data/uploads
src/components/          کامپوننت‌ها (هدر، اسلایدشو، مارکی، فرم‌ها)
data/uploads/            عکس‌های آپلودی توسط ادمین (بکاپ شود!)
public/uploads/samples/  عکس‌های placeholder نمونه
db/custom.db             دیتابیس SQLite (بکاپ شود!)
```
